Technical field notes · 001

What the Theme Park World wrapper changes

Subject:
Windows 11 compatibility
Evidence:
One PC, English 2.0
Status:
Open problems remain

Theme Park World uses DirectDraw and Direct3D calls from the Direct3D 6/7 era. This note sums up how the project's wrapper handles them on Windows 11, and what is still unsolved.

The chain

The game loads ddraw.dll, which loads a modified dxwrapper.dll. That runs the game on Direct3D 9, with settings from dxwrapper.ini. No game files are changed, except one optional resolution setting.

Symptoms and changes

  • Too fast: game speed appears to follow the frame rate. LimitPerFrameFPS = 30 slows it down.
  • Tiny or misplaced picture: DPI scaling is a likely cause. The high-DPI override is set to Application in the file's Properties window.
  • Blocky software look: the game had fallen back from Direct3D. It was seen together with the byte at offset 4 of save\Config.tcf being 00 instead of 01. The first thing to try is choosing Direct3D in the game.
  • Closes at the screen edge: a zero-size cursor copy failed. The wrapper now skips it.
  • Crash entering a park: surface and texture links without multisampling. Changed, with limited retesting.
  • Square next to the cursor: seen with DdrawSkipRenderTargetReadback = 2. The value 1 avoids it.

Still open

The picture can freeze. It was seen at 60 frames per second and at the lowest game speed, and the cause is unknown.

Method

Change one thing at a time, in a copy of the game folder, with a way back. A result counts when the human saw it and the log does not contradict it. The work followed the Human Sandwich Model.

Source

The project's own files hold the details: PROJECT.md, TROUBLESHOOTING.md and INSTALL.md.
